# Bubble Time

손님과 세탁기 6대·건조기 6대를 동시에 관리하는 브라우저 세탁소 운영 게임입니다. 오염에 맞는 도구를 빠르게 골라 기계를 청소하고, 대기 줄이 6명에 도달하지 않도록 매장 사건과 손님 흐름을 관리합니다.

![버블타임 홈 화면](./assets/screenshot-wide.png)

## 현재 상태

- 현재 버전: `2.20.0`
- 배포 방식: GitHub `main` 푸시 후 Vercel 자동 배포
- 기술 구성: HTML, CSS, Vanilla JavaScript
- 저장 방식: 브라우저 `localStorage`
- 온라인 순위·클라우드 저장: 아직 포함하지 않음
- 설치형 실행: PWA 지원

별도의 프레임워크나 빌드 과정 없이 정적 파일만으로 실행됩니다.

## 게임 목표

영업 시간 동안 다음 두 조건을 지키면 영업에 성공합니다.

1. 오염된 기계 사용으로 발생하는 환불을 최대한 줄입니다.
2. 대기 손님이 6명에 도달하지 않도록 깨끗한 빈 기계를 확보합니다.

점수뿐 아니라 환불 수, 손님 만족도, 최고 콤보, 대기 줄, 추가 목표 달성 여부에 따라 최종 등급과 보상이 결정됩니다.

## 영업 모드

| 모드 | 시간 | 특징 |
| --- | ---: | --- |
| 빠른 영업 | 45초 | 홈에서 한 번 눌러 시작하는 날짜별 오늘의 미니 시프트 |
| 기본 영업 | 75초 | 기존 밸런스를 사용하는 표준 모드 |
| 긴 영업 | 120초 | 더 많은 손님과 사건을 관리하는 장기 영업 |
| 무한 영업 | 제한 없음 | 30초 이후 일시정지 화면에서 안전 정산 가능 |

각 모드는 목표 수치와 등급 기준이 플레이 시간에 맞게 조정되며, 최고 점수와 등급도 모드별로 따로 저장됩니다.

튜토리얼을 마친 재방문자의 홈에는 같은 폭의 독립된 2열 카드가 표시됩니다. `오늘의 퀵 시프트`는 날짜별 고정 45초 시나리오를 준비 화면 없이 시작하고, `계획 선택`은 45·75·120초·무한 영업과 난이도·목표를 직접 고르는 화면으로 이동합니다. 두 행동은 겹치지 않는 별도 클릭 영역이라 모바일에서도 목적을 바로 구분할 수 있습니다.

퀵 시프트는 매장 조건·주요 손님·오염·사건·추가 목표가 함께 설계된 12개 수작업 구성으로 순환합니다. 홈의 오늘의 퀵은 같은 날짜에는 동일 시나리오를 유지하며 오늘의 시도 수·최고 점수·최고 별을 별도로 저장합니다. 첫 완주 시 기본 60 수익과 연속 완주 일수에 따른 추가 보상을 받습니다.

| 퀵 시프트 | 실제 규칙 | 세 번째 별 목표 |
| --- | --- | --- |
| 비 오는 번개 세탁 | 물때 청소 점수 +25% | 환불 없이 완주 |
| 주말 45초 러시 | 단골 응대 점수 +25% | 대기 3명 이하 유지 |
| 전력 불안정 | 사건 해결 점수 +35% | 사건을 3초 안에 해결 |
| 이불 세탁의 날 | 대량 세탁 손님 점수 +30% | 만족 손님 4명 |
| 콤보 청소 도전 | 콤보 판정 시간 +1.2초 | 4콤보 달성 |
| 얼룩 전처리 시간 | 얼룩 제거 점수 +30%·얼룩 손님 증가 | 얼룩 손님 2명 전처리 |
| 건조기 먼지 러시 | 건조기 먼지 청소 점수 +35% | 5콤보 달성 |
| 화이트 셔츠 데이 | 얼룩 손님 등장 확률 58%·제거 점수 +35% | 얼룩 손님 3명 전처리 |
| 출근길 익스프레스 | 급한 손님 보상 +35%·인내심 소폭 보정 | 만족 손님 5명 |
| 분실물 정리반 | 놓고 간 빨래 청소 점수 +40% | 환불 없이 완주 |
| 설비 긴급 점검 | 고장 해결 점수 +45% | 사건을 3초 안에 해결 |
| 동네 단골 모임 | 이름 단골 등장 확률 72% | 단골 손님 3명 응대 |

모든 45초 퀵 시프트에는 `준비 → 리듬 → 돌발 → 피날레` 디렉터가 적용됩니다. 초반에는 목표와 도구를 확인할 여유를 주고, 중반부터 손님·오염 간격을 좁히며, 시나리오 대표 사건은 돌발 구간에 예고 후 등장합니다. 피날레에서는 속도가 가장 빨라지지만 모바일 보드 위에 별도 팝업을 띄우지 않고 기존 퀵 안내 리본의 짧은 상태 변화로만 알려 줍니다.

퀵 시프트가 끝나면 `완주`, `오조작 2회 이하`, `시나리오 특별 목표`를 각각 별 하나로 평가합니다. 시나리오별 최고 점수·등급·최고 별·직전 점수와 오조작 수가 저장되며, 결과에서 점수·환불·오조작 변화와 아직 얻지 못한 다음 별 조건을 확인할 수 있습니다. 별이 남아 있으면 같은 조건 재도전을, 3별이면 다음 퀵을 주 행동으로 제안합니다.

누적 별 6·12·18개에서는 각각 전용 간판·바닥·벽지와 수익 보상을 한 번씩 받습니다. 24·30·36개에서는 추가 수익을 받아 12개 시나리오를 모두 3별로 완성하는 장기 목표가 이어집니다. 해금된 장식은 기존 `매장 꾸미기`에서 바로 장착할 수 있습니다.

대기 줄이 처음 6명에 도달하면 즉시 종료되지 않고 `LAST SAVE`가 3초 동안 열립니다. 이 시간 안에 오염이나 사건을 해결해 빈 기계를 확보하면 180점과 함께 영업을 한 번 구조할 수 있으며, 같은 영업에서 두 번째 한계 도달은 즉시 종료됩니다.

### PERFECT와 FEVER

오염 또는 얼룩이 생긴 뒤 1.45초 안에 맞는 도구로 처리하면 `PERFECT` 판정과 20% 점수 보너스를 받습니다. PERFECT를 3회 연속 달성하면 6.5초 `FEVER`가 시작되고 해당 시간의 청소 점수에 1.35배가 추가됩니다. FEVER 중 PERFECT를 다시 달성하면 남은 시간이 6.5초로 갱신됩니다. 오조작이나 느린 대응은 PERFECT 연속 수만 끊으며 이미 시작된 FEVER는 유지됩니다.

PERFECT·FEVER는 기존 콤보 카드, 청소 위치 팝, 보드 가장자리 색과 짧은 음계로 표시합니다. 새 HUD 행을 추가하지 않아 390×844와 360×800 모바일 보드 높이를 그대로 유지합니다. 결과 상세에는 PERFECT 횟수와 FEVER 진입 횟수가 기록됩니다.

## 손님 유형

| 손님 | 특징 |
| --- | --- |
| 일반 손님 | 기본 인내심·작업 시간·보상 |
| 성격 급한 손님 | 인내심이 짧지만 작업이 빠르고 보상이 높음 |
| 단골 손님 | 오래 기다려 주며 보상이 높음 |
| 대량 세탁 손님 | 기계를 오래 사용하지만 큰 보상을 제공 |
| 세탁소 평론가 | 해금 후 드물게 등장하는 고위험·고보상 손님 |

일반 유형과 별도로 민수·지연·하늘·수아·준호·미나 여섯 명의 이름 단골이 반복 방문합니다. 각 단골은 고정된 상의·피부·머리색, 손님 유형과 전용 대사를 가지며 말풍선에 이름이 표시됩니다. 처음 만나면 손님 도감이 열리고, 이후 만족 응대 횟수는 단골별 누적 방문으로 저장됩니다.

일부 손님은 얼룩을 입고 등장하며 기계에 들어가기 전 약 4.6초 동안 전처리 기회를 제공합니다. 이때 얼룩 제거제를 사용하면 높은 청소 점수와 만족도 보너스를 얻습니다. 전처리를 놓치면 영업은 계속되지만 해당 손님의 만족도가 내려가고 결과 코칭에 놓친 횟수가 반영됩니다.

## 튜토리얼과 첫 3판 안내

7단계 실습에서 물때·먼지·남은 세탁물·얼룩 손님·기계 고장·정전·세제 부족을 모두 직접 처리합니다. 첫 완료 보상을 받은 뒤 버튼 하나로 오늘의 퀵 시프트가 바로 시작됩니다.

실습 이후 첫 3판에는 전체 화면을 가리는 팝업 대신 작은 상황 안내만 표시됩니다. 얼룩 손님, 대기 3명, 고장, 정전, 세제 부족, 단체 손님과 위생 검사 예고에 맞춰 필요한 도구나 설비 위치를 알려주며 언제든 닫을 수 있습니다. 첫 영업 결과에서는 보유 수익이 충분하면 첫 도구 강화를 추천합니다.

## 랜덤 매장 사건

| 사건 | 대응 |
| --- | --- |
| 기계 고장 | 정비 렌치로 고장 난 기계 수리 |
| 정전 | 차단기를 눌러 매장 전력 복구 |
| 세제 부족 | 세제 보충통으로 탱크 충전 |
| 단체 손님 | 한꺼번에 들어오는 손님을 위해 빈 기계 확보 |
| 위생 검사 | 제한 시간 안에 매장의 모든 오염 제거 |

사건 발생 전 예고가 표시되며, 빠르게 해결하면 추가 점수와 영업 목표 진행도를 얻습니다. 일일 매장 조건과 주간 사건 규칙에 따라 특정 오염이나 사건이 더 자주 나타날 수 있습니다.

## 성장과 반복 플레이

- 영업마다 무작위 추가 목표 2개 제공
- 수익을 사용한 고속 모터·청소 도구 8단계 강화
  - 고속 모터: 최대 작업 시간 50% 단축
  - 프로 청소 키트: 최대 청소 점수 +84%, 콤보 판정 +2.2초
- 기본 강화 Lv.8 이후 설비별 선택형 마스터 개조 3단계
  - 기계: 터보 회전율(작업 시간 추가 단축) 또는 고객 응대(서비스 점수 증가)
  - 도구: 정밀 세척(청소 점수 증가) 또는 리듬 유지(콤보 판정 증가)
  - 선택한 특화는 수익을 사용해 재설계 가능
  - 첫 마스터 개조는 50% 할인되며, 준비 화면·플레이 HUD·결과 화면에서 활성 효과 확인
- 점장 XP, 레벨, 명성 시스템
- 첫 10회 완주 보상
  - 1·2·4·7·10회차에 각각 ◈ 40·60·90·120·180 지급
  - 기존 저장 데이터는 이미 끝낸 회차를 지급 완료로 이전해 중복 수익을 만들지 않음
- 업적 10종과 일일 도전
- 주간 목표 3종과 주간 플레이 페이스 보상
- 손님·오염·사건·업그레이드 도감
- 간판 11종·바닥 7종·벽지 7종·화분 6종, 총 31종 매장 꾸미기
  - 마스터 특화 Lv.3 완성 시 전용 간판 4종을 무료로 해금
  - 퀵 시프트 누적 별 6·12·18개에서 전용 간판·바닥·벽지 해금
- 최근 10회 영업 기록과 운영 분석
  - 첫 유효 행동 시간, 오조작, PERFECT·FEVER, LAST SAVE 사용·성공 여부를 로컬 상태와 결과에 반영
- S등급·무환불·레벨업 전용 결과 연출과 사운드
- 점수와 등급을 이미지 또는 문구로 공유하는 결과 카드

모바일 플레이에서는 세제 탱크와 전기 차단기를 청소 액션과 같은 50px 높이로 제공하며, 결과 화면의 홈 이동은 재도전·공유 행동과 분리해 오조작을 줄였습니다. 선택한 도구에 맞는 기계·손님·설비는 노란 외곽선으로 연결되어 사건 중에도 올바른 대상을 빠르게 찾을 수 있습니다.

### 영업 수익과 장기 성장

영업 수익은 응대한 손님과 만족 손님을 기본으로 계산하고, 성공 여부와 등급에 따라 추가됩니다. 무환불 완주와 추가 목표 2개 전체 달성에도 별도 보너스가 붙으며, 환불은 건당 수익을 차감합니다.

| 수익 항목 | 보상 |
| --- | ---: |
| 손님 응대 | 1명당 ◈ 12 |
| 만족 손님 | 1명당 ◈ 5 |
| 영업 성공 | ◈ 50 |
| 등급 | S ◈ 90 · A ◈ 60 · B ◈ 35 · C ◈ 15 |
| 무환불 완주 | ◈ 40 |
| 추가 목표 전체 달성 | ◈ 30 |
| 첫 10회 완주 | 1·2·4·7·10회에 ◈ 40·60·90·120·180 |
| 환불 | 1건당 ◈ 8 차감 |

마스터 개조의 기본 비용은 단계별 ◈ 2,200 / 3,200 / 4,400입니다. 계정 전체에서 처음 선택하는 마스터 개조 1회에는 50% 할인이 적용됩니다. 한 특화를 완성하면 전용 업적과 간판을, 기계·도구 양쪽을 모두 완성하면 `마스터 엔지니어` 업적을 얻습니다.

## 화면 구조

자주 방문하는 기능은 팝업을 반복해서 열지 않고 전용 화면 사이를 이동합니다.

```text
홈 ─→ 45초 퀵 시프트 ─→ 게임 → 결과 ─→ 다음 퀵
 └→ 영업 준비 ────────────┘
 └→ 관리 센터
     ├─ 성장: 강화·업적
     ├─ 컬렉션: 도감·꾸미기
     ├─ 기록
     └─ 설정
```

데스크톱 관리 센터는 왼쪽 메뉴와 오른쪽 콘텐츠의 2열 구조이며, 모바일에서는 네 개의 관리 그룹이 화면 아래에 고정됩니다. 관리 기능끼리 이동할 때 배경 블러나 팝업 등장 애니메이션을 반복하지 않고 콘텐츠만 짧게 전환합니다.

실제 오버레이 모달은 일시정지와 영업 중 빠른 설정처럼 현재 흐름을 잠시 중단해야 하는 기능에만 사용합니다. 모바일 홈은 바깥 여백과 둥근 카드가 없는 전체 페이지이며, MANAGER DESK·영업 준비·설정·도움말·업데이트는 홈 오른쪽에서 들어와 `← 홈`으로 돌아갑니다. 복귀 중에는 완성된 홈을 아래에 계속 표시해 화면이 다시 페이드되거나 깜박이지 않습니다. 전용 화면이 열려 있을 때는 배경 게임 화면의 스크롤을 잠가 이중 스크롤을 방지합니다.

### 모바일 화면 원칙

390px 폭을 기준으로 한 모바일 화면은 데스크톱 정보를 단순히 축소하지 않고 우선순위를 다시 구성합니다.

- 홈: 100dvh 전체 페이지에서 `MANAGER DESK`·영업 행동·보조 버튼을 354px 콘텐츠 폭으로 넓히고, 퀵 시작과 계획 선택은 겹치지 않는 동일 폭·동일 높이의 독립 2열 카드로 제공
- 화면 이동: MANAGER DESK·영업 준비·설정·도움말·업데이트를 동일한 좌우 슬라이드 페이지로 전환하고 복귀 시 홈 재등장 애니메이션을 생략. 관리 센터와 설정 탭 사이도 이전·다음 방향에 맞춰 두 페이지가 함께 좌우로 이동하며, 슬라이드 종료 후 기본 페이드가 다시 실행되지 않도록 고정
- 영업 준비: 모드·난이도·오늘의 목표·매장 조건만 먼저 표시하고 완료된 주간 목표 목록은 숨김
- 게임 HUD: 상단·상태·목표 행을 34px·26px·22px, 총 82px로 압축. 남은 시간·매출·환불·일시정지와 콤보·만족도·대기 인원·목표를 유지하면서 최고 기록과 중복 설정·음향 버튼은 영업 중 숨김
- 매장: 기기 폭에 따라 세탁기·건조기 보드 비율을 유지해 390×844에서는 639px, 360×800에서는 약 589px 높이로 표시. 화면이 짧을 때만 전체 조작 UI가 한 화면에 들어오도록 높이를 제한하고, 기계 12대는 계속 3열 2행으로 배치
- 도구판: 여섯 도구를 50px 높이의 3열 2행으로 확대하고 버튼 사이는 2px로 유지. 플레이보드와 도구판의 클릭 영역은 겹치지 않게 분리하고, 보드 테두리만큼의 6~10px 안전 간격으로 바로 이어지도록 배치
- 영업 안내: 퀵 시프트 단계·사건·토스트·첫 영업·LAST SAVE 안내를 상점 헤더의 공통 레일에 배치. 세제·차단기와 기계를 가리지 않으며 여러 안내가 동시에 발생하면 긴급도가 높은 하나만 표시
- 튜토리얼: 목표 HUD가 숨겨져도 639px 기계 보드와 110px 도구판 행을 고정. 얼룩 손님을 포함한 7단계에서 현재 필요한 대상과 도구를 함께 강조하고, 정전·세제 단계에서는 안내 카드를 중앙으로 옮겨 설비를 가리지 않음
- 결과: 주요 정보 간격을 8px로 통일해 핵심 점수와 등급을 먼저 표시하고, 같은 조건의 이전 점수·환불·오조작 변화와 다음 별 조건을 우선 제공. 목표·손님 유형·PERFECT·FEVER·운영 분석은 `상세 영업 기록`으로 접어 제공
- 관리·설정: 하단 네 그룹 탐색을 유지하면서 설명, 버튼, 설정 라벨 글자 크기를 확대

모바일 홈·영업 준비의 핵심 행동과 게임 HUD·기계 12대·도구 6개가 첫 화면 안에 들어오는지 회귀 검사합니다. 설정 진입·탭 전환 후 애니메이션과 불투명도, 390×844·360×800 보드 비율, 보드–도구 안전 간격과 서로 겹치지 않는 헤더 설비·알림 우선순위도 함께 검사합니다.

- 선택한 모드·난이도·추가 목표

- 기계의 오염·고장·작업 진행도

브라우저 데이터나 사이트 저장 공간을 삭제하면 로컬 진행 정보도 함께 사라집니다.

## 온라인 저장 검토: Firebase Firestore

온라인 저장을 추가한다면 Firestore는 현재 구조와 잘 맞는 후보입니다. 정적 Vercel 배포를 유지하면서 웹 SDK로 사용자별 진행 데이터를 저장할 수 있고, Firebase Authentication의 익명 계정은 로그인 화면 없이 사용자별 문서를 보호한 뒤 나중에 정식 계정으로 연결할 수 있습니다.

다만 이번 버전에는 Firebase SDK, 로그인, Firestore 컬렉션, 온라인 순위가 포함되어 있지 않습니다. 로컬 게임이 안정적으로 동작하는 현재 상태를 기준선으로 유지합니다.

### 권장 데이터 구조

```text
users/{uid}
└─ saves/current
   ├─ schemaVersion
   ├─ progression
   ├─ updatedAt
   └─ clientVersion

runs/{runId}
├─ uid
├─ mode
├─ difficulty
├─ score
├─ rank
├─ duration
└─ createdAt
```

### 권장 구현 순서

1. Firebase 프로젝트와 웹 앱을 만들고 Authentication 익명 로그인을 연결합니다.
2. `users/{uid}/saves/current`에 사용자 본인만 읽고 쓸 수 있는 Security Rules를 작성합니다.
3. 로컬 저장을 기본으로 유지하고, 영업 종료나 명시적인 동기화 시점에만 클라우드에 저장합니다.
4. `schemaVersion`과 서버 시간을 사용해 로컬·클라우드 충돌 정책을 정합니다.
5. Firestore Emulator로 권한 규칙과 잘못된 데이터 쓰기를 테스트합니다.
6. App Check를 적용한 뒤 클라우드 저장을 공개합니다.
7. 순위표는 별도 단계에서 추가하고, 클라이언트가 점수를 직접 확정하지 않도록 검증 경로를 둡니다.

2초마다 생성되는 영업 체크포인트는 Firestore에 계속 쓰지 않고 지금처럼 로컬에만 두는 편이 좋습니다. 클라우드는 장기 진행 정보와 완료된 영업 기록에 집중해야 쓰기 횟수와 충돌을 줄일 수 있습니다.

Security Rules는 데이터 접근 권한과 형태를 제한할 수 있지만, 브라우저에서 계산한 점수가 실제 플레이 결과인지 완전히 증명하지는 못합니다. 공개 순위표를 만들 때는 App Check와 함께 Cloud Functions 또는 신뢰할 수 있는 서버 검증을 추가하는 것이 안전합니다.
